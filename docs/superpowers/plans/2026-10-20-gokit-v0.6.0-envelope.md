# gokit v0.6.0: AssetPulse response format as the default

Branch: `feat/v0.6.0` (from `master` = v0.5.1, 51b99fe). This is a breaking change, hence the minor version bump.

## Goal

gokit's JSON responses use AssetPulse's format, so that AssetPulse can move onto gokit with no API change and go-project shares the same format.

**Success:**
```json
{"success": true, "data": ...}
```

**Error:**
```json
{"success": false, "error": {"code": "ERR_...", "message": "..."}}
```

These must match AssetPulse byte for byte (reference: `assetpulse-app/services/*/internal/handler/http/response.go`, `services/pkg/auth/middleware.go`):
- `Content-Type: application/json`.
- The success body has `data` with `omitempty` and no `error` key. The type is `struct{ Success bool json:"success"; Data any json:"data,omitempty" }`.
- The error body has no `data` key.

## Task 1: response, httperror, apperror, middleware

### `response/response.go`
- `type SuccessResponse struct { Success bool `json:"success"`; Data any `json:"data,omitempty"` }`
- `type ErrorBody struct { Code string `json:"code"`; Message string `json:"message"` }`
- `type ErrorResponse struct { Success bool `json:"success"`; Error ErrorBody `json:"error"`; RequestID string `json:"request_id,omitempty"` }`
- Functions:
  - `Success(w, status int, data any)` (unchanged signature)
  - `Error(w, status int, code, message string)`
  - `ErrorWithRequestID(w, status int, code, message, requestID string)`

  `Error` gains a `code` parameter. This break is deliberate: callers must choose a code.
- Exported code constants:

  | Constant | Value |
  |---|---|
  | `CodeUnauthorized` | `ERR_UNAUTHORIZED` |
  | `CodeTokenExpired` | `ERR_TOKEN_EXPIRED` |
  | `CodeTokenRevoked` | `ERR_TOKEN_REVOKED` |
  | `CodeForbidden` | `ERR_FORBIDDEN` |
  | `CodeInvalidInput` | `ERR_INVALID_INPUT` |
  | `CodeNotFound` | `ERR_NOT_FOUND` |
  | `CodeConflict` | `ERR_CONFLICT` |
  | `CodeRateLimited` | `ERR_RATE_LIMITED` |

  | `CodePaymentFailed` | `ERR_PAYMENT_FAILED` |
  | `CodeUnprocessable` | `ERR_UNPROCESSABLE` |

  Services may define their own extra `ERR_*` codes.

### `apperror`
The constructors use the response codes:

| Constructor | Code |
|---|---|
| `Internal` | `ERR_INTERNAL` |
| `BadRequest` | `ERR_INVALID_INPUT` |
| `NotFound` | `ERR_NOT_FOUND` |
| `Forbidden` | `ERR_FORBIDDEN` |
| `Conflict` | `ERR_CONFLICT` |
| `ServiceUnavailable` | `ERR_SERVICE_UNAVAILABLE` |
| `PaymentFailed` | `ERR_PAYMENT_FAILED` |
| `UnprocessableEntity` | `ERR_UNPROCESSABLE` |

`apperror` may import `response` for the constants; `response` must not import `apperror`. The sentinel `Err*` vars stay as they are.

### `httperror`
- `Write` / `WriteWithRequestID` write through `response.Error` / `ErrorWithRequestID`, using the `AppError`'s `Code` and `Message`. They no longer keep their own copy of the struct.
- Any error that isn't an `AppError` gets 500 `ERR_INTERNAL` `"Internal server error"`.

### Middleware messages
These match AssetPulse's exact strings:

| Middleware | Case | Status | Code | Message |
|---|---|---|---|---|
| `rs256.go` | missing or malformed header, bad signature, any other verify failure, missing `sub` | 401 | `ERR_UNAUTHORIZED` | `Authentication required` |
| `rs256.go` | expired | 401 | `ERR_TOKEN_EXPIRED` | `Token expired` |
| `rs256.go` | revoked | 401 | `ERR_TOKEN_REVOKED` | `Token has been revoked` |
| `rs256.go` | revocation check failed, `FailOpen` false | 503 + `Retry-After: 5` | `ERR_SERVICE_UNAVAILABLE` | `Service unavailable` |
| `auth.go` `JWTAuth` | missing or invalid token | 401 | `ERR_UNAUTHORIZED` | `Authentication required` |
| `auth.go` `JWTAuth` | expired | 401 | `ERR_TOKEN_EXPIRED` | `Token expired` |
| `auth.go` `RequireRole` | wrong role | 403 | `ERR_FORBIDDEN` | `Insufficient permissions` |
| `ratelimit.go` | over the limit | 429 | `ERR_RATE_LIMITED` | `Rate limit exceeded` |
| `recovery.go` | panic | 500 | `ERR_INTERNAL` | `Internal server error`, with request ID |

`rs256.go` keeps its existing `FailOpen` behaviour. For `JWTAuth`, split expired from invalid only if the JWT library makes that easy; otherwise use `ERR_UNAUTHORIZED` for both.

## Plan-review rulings (binding; they override the text above where the two differ)

1. **Leaving out empty `data`.**
   - AssetPulse uses a generic `Data T` with `omitempty`. Before encoding, `Success` sets `data` to nil whenever it is empty under encoding/json's `omitempty` rules. Use `reflect`: a zero-length slice, map, array or string, a nil pointer or interface, `false`, or a numeric 0.
   - Zero structs are NOT empty and stay in the output.
   - Golden tests expect `{"success":true}\n` for nil, `[]T{}`, `[]T(nil)`, `map[string]int{}` and `(*T)(nil)`.
   - A non-empty slice and a zero struct both keep `"data"`.
   - Keep `json.NewEncoder`, which writes a trailing `\n`, and pin that newline in the tests.
2. **`httpclient`.**
   - `httpclient/httpclient.go` decodes the new envelope: `error` is `{code, message}`.
   - A `success:false` body must return an error carrying both code and message. It must never fall back to decoding the raw body.
   - Keep plain-JSON (non-envelope) bodies working. Update `httpclient_test.go`.
3. **`JWTAuth` codes.**
   - Splitting expired from invalid is mandatory: `errors.Is(err, jwt.ErrTokenExpired)` gives `ERR_TOKEN_EXPIRED` / `Token expired`.
   - Every other failure, including a missing user identity, gives `ERR_UNAUTHORIZED` / `Authentication required`.
4. **README upgrade section** covers the fail-open differences from AssetPulse's old auth package: gokit's `FailOpen: true` logs a Warn on every lookup failure and gives up on the lookup after `RevocationTimeout` (1s by default). Clients can't see either difference.
5. **`request_id`.** Recovery's 500 adds a top-level `request_id` that AssetPulse never sent. It's an additional field, so it's safe, but document it in the README.
